# Fairdrop

Fairdrop is an embedded Shopify app for product raffles, built with the Shopify React Router app package, TypeScript, Prisma, App Bridge, and Polaris.

## Requirements

- Node.js 22.12 or later
- A Shopify Partner/Dev Dashboard app and development store
- Shopify CLI
- A Resend account and verified sender domain to send winner email

## Local setup

1. Install packages: `npm install`.
2. Copy `.env.example` to `.env`. Set `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SHOPIFY_APP_URL`, and a local `DATABASE_URL`.
3. Set `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY`, and `QSTASH_NEXT_SIGNING_KEY` for automatic draws and claim expiry. Resend is optional: set `RESEND_API_KEY` and a verified-domain `MAIL_FROM` for automatic email, or prepare winner emails in the Winners page and send them manually. Set `QSTASH_ENDPOINT_URL` only if the public expiry route differs from `SHOPIFY_APP_URL`.
4. Link the Shopify app: `npx shopify app config link`. The CLI will populate the app identity and development URLs.
5. Create/update the local database and Prisma client: `npm run setup`.
6. Start the app and Shopify tunnel: `npm run dev`.

Keep `npm run dev` running while using the development preview. Open the **Preview URL** printed by Shopify CLI (or the dev store's active Dev Console preview); the generic `https://shopify.dev/apps/default-app-home` page is Shopify's placeholder, not the Fairdrop app. The root `shopify.web.toml` registers the React Router server with Shopify CLI so the CLI can tunnel requests to the app.

## Vercel deployment

The Shopify app URL and OAuth callback URLs in `shopify.app.toml` must match the deployed host. This repository currently points to `https://probable-lamp-swart.vercel.app`; update it if you switch to a stable production domain, then run `npx shopify app deploy` to publish the app configuration. Set the matching `SHOPIFY_APP_URL`, `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SCOPES`, `DATABASE_URL`, and QStash environment variables in Vercel. Configure `QSTASH_ENDPOINT_URL` to the same public app origin if it differs from `SHOPIFY_APP_URL`.

Shopify must be able to reach the app without a Vercel login or deployment-protection challenge. The Prisma datasource is PostgreSQL; set `DATABASE_URL` in Vercel. The `vercel-build` script runs `prisma migrate deploy` during each build.

The Shopify app requests `read_customers`, `read_discounts`, `write_discounts`, `read_products`, `read_draft_orders`, `write_draft_orders`, `read_orders`, `write_orders`, `read_publications`, `write_publications`, and `write_app_proxy`. Customer profile eligibility checks require the `read_customers` scope and Shopify approval for protected customer data access (including access to the Customer object). Adding the scope alone is not sufficient; request the required access in the Shopify Partner/Dev Dashboard and reauthorize the app after approval. Winner order region validation and cancellation require the order scopes and the `orders/create` webhook. The App Proxy exposes customer entry pages at `/apps/fairdrop/raffles/<handle>` and winner claims at `/apps/fairdrop/claim/<token>`. Changing the app-proxy subpath from `fairdrop` requires reinstalling the app for Shopify to apply the new mapping.

## Workflows

- Create a raffle for an active Shopify product in **Create raffle**. Merchants set a required entry start and deadline, and choose the number of winners. Entry opens at the start time and stops at the deadline; both are enforced on the server. Times are selected in the merchant's browser time zone.
- Raffle eligibility can require a verified customer email, a minimum account age, a phone number, and/or a list of allowed countries. Country eligibility uses the country on the customer's default address, not geo-IP. The default account age is zero days; when configured, the account must predate the raffle announcement by at least that age. Shipping country must be re-verified when the prize order is created before enabling production draws.
- After creating a raffle, use the **Set up your storefront** instructions in the app dashboard or creation confirmation to choose a theme and open Shopify's theme editor. On a compatible Online Store 2.0 theme, open the page template where the entry form should appear, choose **Add section > Apps > Fairdrop raffle entry**, reposition the block, customize its heading, and save. App blocks require JSON templates and a section that supports app blocks; vintage themes aren't supported by the block. The block automatically displays every raffle whose entry window is currently open for that store; raffle product details and rules come from Fairdrop, so no raffle handle is needed in the theme editor.
- The storefront entry form shows the raffle product image and lets customers choose from currently available product options (such as size and color). Their selected variant is saved with the entry; if they win, their Draft Order and the order eligibility check use that exact variant at its regular price.
- Merchants can enable **Keep this product off the Online Store until winner claims are settled** when creating a raffle. This unpublishes the entire product, including all variants, only from the Online Store; other Shopify sales channels remain unchanged. Fairdrop records whether the product was published and restores it after all claims settle, preserving a pre-existing future publication time when applicable. The setting needs Shopify `read_publications` and `write_publications` scopes and QStash configured so the signed safety worker runs during the entry window. A product that was unpublished before the raffle stays unpublished afterward. For raffles with a future start, restriction begins on the next safety sweep (within 10 minutes); products already accepting entries are unpublished immediately during raffle creation. Place the entry block on a published page other than the raffled product page, since the product page will be unavailable during the raffle.
- Merchants can edit an undrawn raffle from the dashboard. The raffle name and customer-facing description can be updated while its status remains active; before the existing deadline, the deadline can only be extended. Product, winner count, entry rules, and Online Store restriction are not editable after creation so current participants and winner allocations are not changed retroactively.
- Closed raffles are drawn automatically by a signed QStash message at the deadline when it is within the QStash scheduling horizon; otherwise, the self-scheduling safety sweep draws within about 10 minutes. The safety sweep also recovers failed work. Selected entrants receive their existing account-bound winner claim emails when automatic email is configured; otherwise, merchants can prepare and send winner claim emails manually from the Winners page. Other entrants receive a not-selected email when automatic email is configured and may remain eligible for promotion if a winner's claim expires. Outcome emails and coupon delivery are retried by the safety sweep if delivery fails. For raffles with **Keep this product off the Online Store until winner claims are settled** enabled, the product remains unpublished through the draw, claim periods, and waitlist promotions, and is restored only after all units are purchased or marked unsold. This restriction is Online Store-only and requires `read_publications`/`write_publications`.
- A merchant can optionally configure a unique one-use Shopify discount for each non-winner when creating a raffle. Codes apply to the whole order, are restricted to that entrant's Shopify customer account, and expire 1–365 days after the draw. Percentage offers range from 0.01% to 100%; fixed values use the shop's currency. Shopify `read_discounts` and `write_discounts` scopes are required. If a discount fails to create, the entrant still receives the not-selected email and Fairdrop retries the coupon and sends it separately.
- Automatic drawing and entrant emails require the signed QStash sweeper to be configured before a new raffle can be created. The sweeper is self-scheduled; it does not use Vercel Cron.
- Entries are accepted only during the scheduled window, submitted through Shopify's signed App Proxy, and require a logged-in Shopify customer account. Prisma enforces one entry per raffle per Shopify customer ID, canonicalized email address, normalized phone number, and complete default shipping address. Phone and address duplicate keys are HMAC-SHA-256 values; raw phone and address values are not copied into entry records. Shared households or phone numbers are treated as duplicate identities for the same raffle. Entry forms also include a server-signed, short-lived submission proof, a hidden honeypot, a minimum completion time, and a persistent limit of five attempts per customer per store in each 10-minute window. Apply database migrations during deployment for the rate-limit buckets and entry identity hashes. These measures deter basic automation; a managed CAPTCHA such as Turnstile can be added for higher-risk stores. Existing entries predating the identity-hash migration are still protected by customer ID and email, but require a new entry to have a matching stored phone/address hash for those additional checks to apply.
- Entry email addresses must match the customer's Shopify profile. Email identity keys are SHA-256 hashes of normalized addresses (lowercase, plus-tags removed, and Gmail/Googlemail dots and aliases canonicalized); the original address casing is retained for winner notifications. Common disposable-email services are blocked.
- Draws use cryptographically secure sampling without replacement and persist a random entry ranking for the waitlist. Each winner gets a Draft Order for exactly one selected variant at its regular price, attached to their Shopify customer and email. Shopify reserves the inventory until the raffle's configured claim deadline (default 2,880 minutes; test raffles can use a 2-minute window).
- Fairdrop creates a 32-byte random claim token and stores only its SHA-256 hash. The winner email contains the App Proxy claim URL, never Shopify's invoice URL. Claim requests require a valid Shopify App Proxy signature and the winning customer to be logged in; the single-use-to-purchase link then redirects to the Draft Order invoice URL with no-store/no-referrer headers. Purchase makes the allocation unusable. Resending rotates the token and invalidates the previous claim link.
- Merchants without a verified sender domain can use **Prepare manual email** on the Winners page. Fairdrop rotates the claim token and displays a ready-to-copy email with the customer's address, subject, secure App Proxy claim link, and deadline; the Shopify invoice URL is never shown. The token is stored only as a hash and displayed only in the action response, so copy and send it before navigating away. Preparing another manual email invalidates the earlier link. Merchants can mark the email sent after sending it from their own account. QStash remains required for scheduled draws, claim expiry, and waitlist promotion.
- Shipping eligibility is verified from the actual order's shipping address by the `orders/create` webhook. When a raffle has an allowed-country list and the order country is not on it, Fairdrop cancels and refunds the order to the original payment method, restocks inventory, and marks the allocation cancelled. The order webhook also checks the attached customer and one-unit raffle variant before marking a purchase successful.
- Fairdrop publishes a signed QStash delayed message for every claim deadline. The signed `/api/expire-winners` handler also self-schedules a QStash sweeper every 10 minutes as a recovery path; do not use Vercel Cron on Hobby for this. Configure a public HTTPS app URL reachable by QStash and copy the token plus current/next signing keys from the Upstash QStash console into the deployment environment. The delayed jobs and sweeper are signature-verified, idempotent, and use QStash retries.
- Expiry claims the allocation with an atomic conditional status update in a database transaction; the unique allocation-per-entry constraint prevents concurrent promotions from allocating the same entrant twice. QStash retries failed deliveries. Before deleting a draft, Fairdrop queries Shopify again for completed/paid state; if still unpaid it deletes the draft, audits the expiry, and promotes the next never-allocated eligible entry in the persisted draw ranking. Exhausted positions are counted as unsold. The invoice URL has no Shopify-native per-link expiry, so deletion releases any remaining reserved stock.
- Completed raffle data is retained for 30 days, then the raffle, entries, winners, allocations, and related audit logs are cascade-purged. QStash delayed messages are limited to seven days, so each purge is scheduled in stages no more than six days apart until its retention deadline. The 10-minute recovery sweeper also finds missing purge schedules and deletes due raffles if a delayed message is lost.

### Winner email sender domain

The simplest and recommended multi-merchant setup is one Fairdrop-operated sender domain verified with Resend. Configure `MAIL_FROM` with that verified address and `RESEND_API_KEY` in the app deployment. Fairdrop uses the merchant's Shopify store name as the display name; each merchant can optionally set a reply-to address and customize the subject/body in **Settings**. A reply-to address does not authorize sending from the merchant's domain. Merchants can use manual winner emails if the operator has not configured a verified sender.

If each merchant must send from its own domain, implement provider-managed sender-domain onboarding rather than accepting arbitrary `From` addresses. The merchant must prove domain ownership and publish the provider-specific DNS records (typically SPF and DKIM; configure DMARC as well). Prefer a dedicated subdomain such as `raffle.example.com`, keep SPF within the DNS single-record limit, and wait for provider verification before enabling that sender. The app must store the verified sender/domain-to-shop association and only allow mail from verified domains. A shared Fairdrop sender avoids per-merchant DNS onboarding and is appropriate while using merchant display names and reply-to addresses.

## Database and deployment

The database is PostgreSQL. Set `DATABASE_URL` to a Postgres connection string locally and run `npm run setup` to apply migrations.

Configure the Shopify app's production URL and deploy with `npx shopify app deploy`. Keep the app proxy, access scopes, order/payment/draft-order webhook subscriptions, and privacy webhooks in `shopify.app.toml`. Reauthorize/reinstall the app after changing scopes, webhook subscriptions, or App Proxy mapping. Set up the QStash token and signing keys, and verify the Resend sender domain before enabling winner draws. Apply all Prisma migrations before using winner allocation workflows. Shopify order webhooks are authenticated by the Shopify app's webhook authenticator (HMAC verification); webhook IDs are persisted to make replay handling idempotent.

The customer data request webhook logs the number of matching entries so the merchant can respond with the stored raffle data. Customer redaction removes matching entries (and cascades associated winner and allocation rows); shop redaction removes sessions and shop raffle data.
